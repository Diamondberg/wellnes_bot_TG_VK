- [ ] Получить и сохранить (у себя, НЕ в чат):
  - App ID (публичный, можно в чат)
  - Secure key (секрет)
  - Service token (секрет)
  - ID группы (число)
  - Community access token с правами `messages`, `manage` (секрет)

**Когда готово → пользователь пишет "готово, App ID = ...". Дальше план:**

1. Фронт: определение платформы (TG / VK / браузер), VK Bridge подключается рядом с TG WebApp.
2. Бэкенд: endpoint для валидации VK launch params (подпись secure key).
3. БД: использовать `vk_user_id`, корректное определение `first_platform`.
4. VK-бот: Long Poll для группы — приём событий, отправка уведомлений рефереру в личку через VK API.
5. Шаринг через VK Bridge (поделиться на стене / в группе / другу).

**Принципы:**
- Все VK credentials — через `.env` (App ID, Secure key, Service token, group ID, community token).
- Никаких хардкодов под "один арендатор" — используем `settings.tenant_code`.
- ЛК для редактирования `.env` — НЕ сейчас, отдельный этап.

## 6. Известные тонкости

- В коде везде заложен `tenant_id`. Сейчас всегда `default` — не убирать, под SaaS.
- Юзеры в БД мэтчатся по **телефону в рамках tenant'а**. Один человек = одна запись на tenant.
- В `frontend/index.html` ключ localStorage: `wellness_app_state_v1`. В стейте лежит `ownerId` (TG user id или null в браузере).
- Реферальная ссылка TG: `https://t.me/WellnessTest_bot?start=invite_<platform_user_id>`.
- Фоллбэк-реферер = дистрибьютор (если ссылка без invite или invite битый).
- В браузере вне TG `currentUserPlatformId` возвращает заглушку `999000111` — это нужно для генерации реф-ссылок. `ownerId` (для проверки владельца localStorage) возвращает `null`. Не путать.
